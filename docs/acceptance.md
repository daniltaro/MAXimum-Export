# Критерии приёмки и тесты

Каждый критерий проверяется тестом. Отчёт о приёмке — это вывод одной команды:

```bash
go test ./internal/flow/ -run Acceptance -v
```

В Docker, без установки Go:

```bash
docker run --rm -v "$PWD":/src -w /src golang:1.24-alpine go test ./internal/flow/ -run Acceptance -v
```

Результат последнего прогона: **17 сценариев ведущего, все 16 тестов пройдены**,
самый долгий ответ на расчёт — 262 мкс (порог приёмки — 5 с).

## Функционал (база)

| Критерий | Тест | Что именно проверяется |
|---|---|---|
| Выбор 3 стран с корректным режимом (ЕАЭС / не ЕАЭС) | `TestAcceptanceThreeCountries` | Китай → «Режим „Третьи страны“», Армения и Казахстан → «Режим ЕАЭС»; режим повторён строкой «Страна: … (ЕАЭС \| вне ЕАЭС)» в отчёте |
| Принимает тип продукции и код ТН ВЭД (подбор + ручной ввод) | `TestAcceptanceProductAndCodeInput` | «сахар-песок» → список кодов, выбор кнопкой; «Указать код вручную» → `0409 00 000 0` принят |
| Валидация веса и количества | `TestAcceptanceValidation` | «Турция» → страна вне MVP; `0`, `-5`, «абв» в количестве; `0` в весе; вес 5 кг на 1 000 мешков → «5 кг или 5 тонн?» |
| Расчёт пошлины (тип, формула, итог) либо «0 ₽» для ЕАЭС | `TestAcceptanceDutyCalculation` | рапс → Китай: комбинированная ставка, обе формулы, итог 1 650 000 ₽ + сбор 21 344 ₽; сахар → Китай: «ставка не установлена», 0 ₽; мёд → Армения: «не применяется (ЕАЭС)», 0 ₽, курс не нужен |

## Сценарии (включая нестандартные)

| Критерий | Тест | Что именно проверяется |
|---|---|---|
| Полный путь для Китая: все блоки + дисклеймер | `TestAcceptanceFullPathChina`, `TestScenario1ChinaSugar` | 8 блоков отчёта по порядку, дисклеймер MVP, файл `.txt` приходит сразу |
| Полный путь для ЕАЭС: нулевая пошлина, статформа, требования ЕАЭС | `TestAcceptanceFullPathEAEU`, `TestScenario2ArmeniaHoney` | «Итого к уплате: 0 ₽», статистическая форма вместо декларации, ТР ТС и маркировка ЕАЭС |
| 5+ нестандартных ситуаций без зависаний, с ⚠️/🚫 | `TestAcceptanceNonStandardSituations`, `TestDemoScenarios` | запрет вывоза (🚫), квота на зерно, устаревший код, сбой курса, нетипичный вес; после каждого ответа бот предлагает следующий шаг |

## Интерфейс и UX

| Критерий | Тест | Что именно проверяется |
|---|---|---|
| Прогресс «Шаг N из 4», кнопки «Назад», «Изменить», «Скопировать» | `TestAcceptanceProgressAndButtons`, `TestBackFromEveryStep` | все четыре шага подписаны; «Назад» возвращает на шаг раньше; «Изменить» открывает правку с сохранением остальных данных; «Скопировать» укладывается в одно сообщение (≤ 4000 символов) |
| Блоки в фиксированном порядке; при длине > 3500 символов — разбивка | `TestAcceptanceReportStructure` | для **всех** пищевых кодов × 3 стран: порядок блоков `params → packaging → product → labeling → documents → lab → duty → roles → warnings`, каждая часть ≤ 3500 символов и подписана «(N/M)» |
| Читаемо на планшете и ноутбуке | `TestAcceptanceTabletReadable` (+ ручная проверка) | кнопки по одной в ряд, подписи ≤ 30 символов, нет неразрывных кусков длиннее 45 символов (горизонтальный скролл). Размер шрифта и кнопок рисует клиент MAX — проверяется вручную на планшете |

## Эксплуатация и безопасность

| Критерий | Тест | Что именно проверяется |
|---|---|---|
| Время отклика ≤ 5 с; 20 расчётов подряд | `TestAcceptanceResponseTime`, `TestTwentyCalculationsInARow` | 20 полных расчётов подряд, замеряется самый долгий ответ (262 мкс на расчёт; сетевая задержка MAX в чате — доли секунды) |
| Нет запроса персональных данных | `TestAcceptanceNoPersonalData` | все 290 текстов бота проверяются регулярными выражениями на ФИО, телефон, e-mail, ИНН/ОГРН, номер и цену контракта; присланные телефон, ИНН, номер контракта и e-mail бот отклоняет и не использует как запрос товара |
| Учебные данные помечены; на каждом результате дисклеймер MVP | `TestAcceptanceTrainingDataMarked`, `TestAllCombinations` (internal/report) | «учебный курс», «учебная оценка» в блоке пошлины, дисклеймер в чате и в файле, дисклеймер во всех 17 сценариях режима ведущего |

## Готовность к тренингу

| Критерий | Тест | Что именно проверяется |
|---|---|---|
| Путь «старт → результат» ≤ 3 минут, 3 из 4 контрольных вопросов | `TestAcceptanceTrainingPath` | путь занимает 8 действий (6 из них — нажатия кнопок); бот отвечает на все 4 вопроса: сертификаты (GACC), пошлина (0 ₽), срок регистрации (2–6 мес.), язык маркировки (китайский) |
| Для 5 ролей минимум 1 релевантный блок | `TestAcceptanceFiveRoles` | в блоке «👥 Кому что важно» по строке для директора ВЭД, менеджера, таможенного эксперта, бухгалтера и экспортного контроля — по всем трём странам |
| Ведущий показывает 5 нестандартных сценариев без сбоев | `TestAcceptanceTrainerMode` | `/demo` → 17 сценариев, каждый отрабатывает и оставляет кнопки для продолжения |

## Что проверяется руками

Автотесты гоняют бота через то же ядро, что и MAX, но три вещи видит только человек:

1. **Бот доступен по ссылке** — https://max.ru/t747_hakaton_max_bot, команда `/start` отвечает.
2. **Читаемость на планшете и ноутбуке** — открыть бота на планшете, пройти сценарий 1: кнопки
   нажимаются пальцем, текст переносится, горизонтального скролла нет.
3. **Нетехнический пользователь за ≤ 3 минут** — дать человеку без опыта ВЭД пройти
   «Начать расчёт → 🇨🇳 Китай → сахар-песок → 5000 → 250000 → Рассчитать» и задать 4 вопроса
   кнопкой «Задать вопрос».

Пошаговый сценарий проверки для жюри — в [README.md](../README.md), раздел «Пошаговый сценарий проверки».
