# MAXimum Export

Чат-бот в мессенджере MAX: по четырём параметрам сделки (страна, продукт с кодом ТН ВЭД,
количество, вес) выдаёт готовый отчёт — требования к упаковке, продукции и маркировке,
перечень сертификатов и лабораторных испытаний, расчёт вывозной пошлины и таможенного сбора.
Страны назначения: Китай, Армения, Казахстан.

**Работающий бот: https://max.ru/t747_hakaton_max_bot** — откройте и отправьте `/start`.

> ⚠️ Это демонстрационный прототип (MVP) для тренинга. Справочники учебные, собраны
> по состоянию на 20.09.2026. Результат не является официальной консультацией — проверьте
> данные у таможенного брокера. Дисклеймер выводится под каждым отчётом бота.

## 1. Назначение решения

Специалист по ВЭД тратит часы на поиск разрозненных требований: нормы страны назначения,
перечень разрешительных документов, ставки пошлин, курс валюты. Бот собирает это в один
структурированный отчёт за минуту.

Что делает решение: проверяет код ТН ВЭД по справочнику (существует ли, пищевой ли,
не заменён ли новым); определяет режим расчёта — ЕАЭС (Армения, Казахстан: пошлин нет)
или третья страна (Китай); считает пошлину по типу ставки (адвалорная, специфическая,
комбинированная, не установлена) и таможенный сбор; собирает требования страны назначения
по блокам и добавляет предупреждения о запретах, квотах, устаревших кодах, нетипичном весе
и сбоях курса; отдаёт результат сообщениями в чат и отдельным файлом `.txt`.

Вне MVP (ТЗ §19): проверка контрагентов, подбор инкотермс, генерация документов, расчёт
логистики, отслеживание груза, валютный контроль, уведомления об изменении ставок.

Сценарий 1 из ТЗ §22: менеджер по ВЭД, первая поставка сахара-песка в Китай.

| Шаг | Пользователь | Что он видит |
|---|---|---|

| 2 | «Начать расчёт» | «Шаг 1 из 4. Выберите страну экспорта» — 🇨🇳 Китай, 🇦🇲 Армения, 🇰🇿 Казахстан |

Блоки отчёта идут в фиксированном порядке: параметры сделки → упаковка → продукция →
маркировка → сертификаты и разрешения → лабораторные испытания → таможенная пошлина →
«Кому что важно» (пять ролей ТЗ §21) → предупреждения → дисклеймер MVP. После отчёта доступны
пять кнопок: «📋 Скопировать отчёт», «📄 Скачать отчёт», «🔄 Новый расчёт»,
«✏️ Изменить данные», «❓ Задать вопрос».
Для быстрой демонстрации на стартовом экране есть кнопка **«Пример заполнения»** — она сразу
считает этот сценарий на тестовых данных ТЗ §9.

## 3. Состав и архитектура решения

Решение — **одна программа на Go** (`cmd/app`). Внутри неё работают чат-бот MAX и служебный
HTTP API. Отдельных сервисов, очередей и баз данных нет.

Главный принцип: **расчётное ядро ничего не знает о мессенджере.** Пакет `engine` работает
со структурами `Input`/`Result`, `flow` описывает диалог в терминах «сообщение и кнопки»,
и только `maxbot` переводит это в вызовы MAX Bot API. Поэтому тот же диалог запускается
в терминале (`cmd/chat`) без мессенджера и без интернета.

```
 Мессенджер MAX  ──long polling──▶ internal/maxbot ─┐  адаптер MAX
                                                    │
                                 internal/flow  ◀───┘  экраны 1–6, шаги 1–4, /demo
                                        │
 Браузер / curl  ──HTTP──▶ internal/api │              JSON, CORS, лимит частоты
                                   │    │
                                   ▼    ▼
                        internal/service + store       расчёты в памяти, 24 ч
                                   │
                                   ▼
                        internal/engine — ЯДРО  ──▶ report (чат, .txt, копия)
                        коды, ввод, пошлины,        faq (справка и ответы)
                        курс, предупреждения        texts/ru.json (290 ключей)
                                   │
                                   ▼
                        data/ — справочники JSON (go:embed)
```

| Папка | За что отвечает |
|---|---|
| `cmd/app` | Боевая программа: бот MAX и HTTP-сервер, корректная остановка по сигналу |
| `cmd/chat` | Тот же диалог в терминале: кнопки пронумерованы, файлы падают в `reports/` |
| `cmd/report` | Печать отчёта по параметрам командной строки — проверка ядра без интерфейсов |
| `internal/engine` | Ядро: поиск и проверка кодов, разбор ввода, формулы пошлин, курс, предупреждения §14 |
| `internal/service` | Операции, общие для чат-бота и API: поиск, валидация, расчёт, вопросы |
| `internal/flow` | Диалог: экраны 1–6 ТЗ §15, шаги 1–4, сессии, режим ведущего `/demo` |
| `internal/maxbot` | Адаптер MAX: long polling, очередь сообщений по чатам, паузы и повторы отправки |
| `internal/api` | Служебный HTTP API (JSON) и `openapi.yaml` |
| `internal/report` | Отчёт в трёх видах: сообщения чата, документ `.txt`, краткая копия |
| `internal/faq` | Справка (экран 6) и ответы на вопросы по готовому расчёту |
| `internal/store` | Расчёты в памяти: TTL 24 часа, не более 10 000 штук |
| `internal/config` | Чтение `.env` и переменных окружения |
| `data` | Учебные справочники JSON, вшитые в программу |
| `texts` | Все тексты интерфейса одним файлом `ru.json` |

## 4. Запуск одной командой

Из корня проекта:

```bash
cp .env.example .env     # один раз: вписать BOT_TOKEN
docker compose up --build
```

Поднимается один контейнер `maxexport`: чат-бот подключается к MAX, служебный API слушает
`http://127.0.0.1:8080`. Остановка — `Ctrl+C`.

Без `BOT_TOKEN` команда тоже работает: бот не запускается, API доступен — этого достаточно,
чтобы проверить расчёты.

Проверено: образ собирается, контейнер поднимается со статусом `healthy`, в журнале
появляется `MAX: бот @t747_hakaton_max_bot (Хакатон МАХ 747) запущен, жду сообщений`.

## 5. Необходимые параметры окружения

| Что нужно | Зачем |
|---|---|
| Docker с плагином Compose | Единственное требование для запуска. Проверено на Docker 29.7.2 |
| Токен бота MAX | Выдаёт `@MasterBot` в мессенджере MAX. Без токена работает только API |
| Доступ в интернет | Бот сам опрашивает серверы MAX. Домен, HTTPS и белый IP **не нужны** |
| Go 1.24+ | Только для локальной разработки: `go test ./...`, `go run ./cmd/chat` |

Сервер для боевого запуска: 1 ядро, 1 ГБ памяти, 10 ГБ диска, Ubuntu 22.04/24.04 —
подробности в [`docs/deploy.md`](docs/deploy.md).

## 6. Переменные окружения

Задаются в `.env` (создаётся из `.env.example`). Переменные окружения важнее `.env`.
Файл `.env` исключён из git и из Docker-образа — токен в репозиторий не попадает.

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `BOT_TOKEN` | пусто | Токен бота MAX от `@MasterBot`. Пусто — бот не запускается, работает только API |
| `HOST` | `0.0.0.0` | Адрес, на котором слушает HTTP-сервер внутри контейнера |
| `PORT` | `8080` | Порт HTTP-сервера |
| `RATE_SOURCE` | `training` | `training` — учебный курс (1 € = 100 ₽); `cbr` — курс ЦБ РФ с обновлением раз в час |
| `ALLOWED_ORIGINS` | `*` | CORS: с каких адресов можно обращаться к API из браузера, через запятую |
| `TRUST_PROXY` | `false` | `true`, если перед программой стоит обратный прокси: адрес клиента из `X-Forwarded-For` |

## 7. Используемые порты

| Порт | Кто | Доступ |
|---|---|---|
| 8080 | Служебный HTTP API и `/healthz` | В compose опубликован как `127.0.0.1:8080:8080` — только с самой машины |

**Входящие порты для бота не нужны.** MAX-бот работает через исходящий long polling:
программа сама подключается к серверам MAX. Ни домена, ни сертификата, ни проброса портов
не требуется.

## 8. Зависимости

| Что | Версия | Откуда |
|---|---|---|
| Внешняя библиотека | `github.com/max-messenger/max-bot-api-client-go/v2 v2.4.0` | `go.mod` — официальный клиент MAX Bot API |
| Go | 1.24 | `go.mod` (`go 1.24.0`), образ сборки `golang:1.24-alpine` |
| Базовый образ | `alpine:3.20` | `Dockerfile`, второй этап сборки |

Прямая зависимость ровно одна. Всё остальное — стандартная библиотека Go: HTTP-сервер, JSON,
XML (разбор ответа ЦБ), `embed`, `crypto/rand`. Файл `go.sum` фиксирует контрольные суммы
версий, включая транзитивные записи библиотеки MAX (`stretchr/testify`, `go.yaml.in/yaml/v3`),
поэтому сборка воспроизводима. Сборка идёт с `CGO_ENABLED=0`: статический бинарник,
итоговый образ около 26 МБ, запущенный контейнер занимает около 12 МБ памяти
(измерено `docker image ls` и `docker stats`).

## 9. Внешние сервисы и интеграции

| Сервис | Обязателен | Назначение | Условия проверки |
|---|---|---|---|
| **MAX Bot API** | да, для чат-бота | Приём сообщений и отправка ответов через long polling | Нужны `BOT_TOKEN` от `@MasterBot` и доступ в интернет. В Docker поднять нельзя — это внешний сервис мессенджера. Без него проверяются только расчёты: консольный чат и API |
| **ЦБ РФ** (XML) | нет, по умолчанию выключен | Официальный курс валют | Включается `RATE_SOURCE=cbr`. Курс обновляется в фоне раз в час, ответ пользователю не ждёт сайт ЦБ. При недоступности расчёт идёт по последнему известному курсу с пометкой ⚠️ (ТЗ §14.8) |

Серверы MAX используют сертификат Минцифры «Russian Trusted Root CA», которого нет в списке
доверенных ни в Alpine, ни в macOS. Сертификат скачивается с сайта Минцифры **при сборке
образа**, его отпечаток SHA-256 проверяется (иначе сборка падает), и ставится **только внутрь
контейнера** — на систему разработчика это не влияет. Без него бот не подключится к MAX:
`certificate signed by unknown authority`.

## 10. Работа с данными

Базы данных нет — по ТЗ §19 она не входит в MVP.

**Справочники** вшиты в программу через `go:embed`: копировать их на сервер или монтировать
в контейнер не нужно.

| Файл | Что внутри |
|---|---|
| `data/tnved.json` | 58 позиций ТН ВЭД: код, название, ключевые слова для поиска, категория, происхождение (животное/растительное), типичный вес единицы, доля тары, учебная цена за тонну, температурный режим. 56 пищевых и 2 непищевых — для проверки сообщения «код не относится к пищевой продукции» |
| `data/measures.json` | Меры регулирования: 37 записей о ставках пошлин, 2 квоты, 1 запрет вывоза, 4 запрета ввоза, шкала таможенных сборов (8 ступеней) и фиксированный сбор 8 262 ₽ |
| `data/countries/{cn,am,kz}.json` | Профили стран: требования к упаковке, продукции, маркировке; перечни документов и испытаний по группам товаров; налоги, логистика, тексты для пяти ролей |

Данные **учебные**, собраны на дату `20.09.2026` (поле `data_as_of`) — она выводится
в каждом отчёте. Учебные значения помечены в тексте: курс 1 € = 100 ₽, «таможенная стоимость
(учебная оценка)».

**Расчёты** хранятся в памяти процесса (`internal/store`): TTL 24 часа, не более 10 000 штук —
чтобы можно было скачать `.txt`, задать вопрос по отчёту и увидеть «С возвращением!».
После перезапуска программы расчёты и сессии теряются — так и задумано по ТЗ §19.

**Персональные данные** бот не запрашивает, не принимает и не логирует (ТЗ §17, §18).
На старте выводится напоминание: «🔒 Персональные данные не нужны: не присылайте ФИО,
телефоны, e-mail, ИНН, номера и цены контрактов». Если пользователь всё же прислал похожее
на ПД, ввод отклоняется с пояснением и сообщение не сохраняется. В журнал попадают только
метод, путь и код ответа — без текстов пользователей.

## 11. Порядок работы с тестовыми данными

Тестовые данные ТЗ §9 заложены в бота: Китай, сахар-песок свекловичный, код ТН ВЭД
**1701 12 100 0**, **5 000 мешков**, **250 000 кг** (250 т, брутто).

Как их запустить:

1. **Кнопка «Пример заполнения»** на стартовом экране — сразу показывает готовый отчёт
   с пометкой «🧪 Пример заполнения на учебных данных».
2. **Режим ведущего:** команда `/demo` открывает список из **17 сценариев**, каждый
   запускается одной кнопкой. Первые три — сценарии ТЗ §22 (Китай/сахар, Армения/мёд,
   Казахстан/мука с весом «5»), остальные 14 показывают нестандартные ситуации §14: запрет
   вывоза, квота на зерно, запрет ввоза страной назначения, устаревший код, замена кода
   до отгрузки, сбой курса, скачок курса на 5 %, недоступность справочника ТН ВЭД,
   недоступность профиля страны, устаревшие данные, температурный режим, спорный код,
   компонент под ограничением, испытания не успевают к отгрузке.
3. **Командная строка:** `go run ./cmd/report` — тот же сценарий 1 в терминале.

**Как менять справочники.** Отредактируйте JSON в `data/` и пересоберите программу — файлы
вшиваются при сборке. Загрузчик включает `DisallowUnknownFields`: опечатка в имени поля даёт
ошибку сразу, а не тихо пропущенные данные. Проверка — `go test ./data/`: справочники
загружаются, коды не повторяются, у каждой страны есть все товарные группы, у каждого
пищевого кода есть запись о пошлине, меры и шкала сборов непротиворечивы.

## 12. Пошаговый сценарий проверки

**А. Работающий бот (быстрее всего).** Откройте **https://max.ru/t747_hakaton_max_bot**,
отправьте `/start` → «Начать расчёт» → 🇨🇳 Китай → «сахар-песок» → код `1701 12 100 0` →
`5000` → `250000` → «✅ Рассчитать». Должны прийти три сообщения отчёта и файл `.txt`.
Команда `/demo` открывает 17 сценариев ведущего.

**Б. Локальный запуск в Docker:**

```bash
cp .env.example .env          # вписать BOT_TOKEN, либо оставить пустым
docker compose up --build     # сборка и запуск
docker compose ps             # STATUS должен быть "Up ... (healthy)"
docker compose logs -f        # журнал: строка о подключении к MAX
```

**В. Расчёты без мессенджера.** `go run ./cmd/chat` — тот же диалог в терминале (номер
нажимает кнопку, `/exit` — выход). Отчёт по параметрам командной строки:

```bash
go run ./cmd/report                                                       # Китай, сахар (ТЗ §9)
go run ./cmd/report -country am -code 0409000000 -qty 200 -weight 4000    # Армения, мёд
go run ./cmd/report -country kz -code 1101000000 -qty 1000 -weight 5      # Казахстан, ошибка в весе
go run ./cmd/report -country cn -code 1205109000 -qty 100 -weight 100000  # рапс, комбинированная ставка
go run ./cmd/report -txt                                                  # текстовый документ .txt
```

**Г. Служебный API** (контейнер запущен):

```bash
curl -s http://127.0.0.1:8080/healthz
curl -s http://127.0.0.1:8080/api/v1/meta
curl -s "http://127.0.0.1:8080/api/v1/products/search?q=сахар"
curl -s -X POST http://127.0.0.1:8080/api/v1/calculations \
     -H 'Content-Type: application/json' \
     -d '{"country":"cn","code":"1701121000","quantity":5000,"weight_kg":250000}'
```

Последний запрос возвращает `201` и полный расчёт: `blocks`, `documents`, `duty`, `warnings`,
`roles`, `chat_parts`, `copy_text`, `download_url`. По значению поля `id` доступны
`GET /api/v1/calculations/{id}/report.txt` и `POST /api/v1/calculations/{id}/questions`.
Полное описание — `internal/api/openapi.yaml` и `GET /api/v1/openapi.yaml`.

**Д. Проверка кода:** `go test ./...` — проходят все пакеты. Приёмка по критериям ТЗ §21
(16 тестов, включая прогон всех 17 сценариев `/demo`) — `go test ./internal/flow/ -run Acceptance -v`;
какой тест закрывает какой критерий — в [`docs/acceptance.md`](docs/acceptance.md).

## 13. Примеры ожидаемого поведения

Значения получены командой `go run ./cmd/report` на учебных данных (курс 1 € = 100 ₽).

**Сценарий 1 ТЗ. Китай, сахар-песок 1701 12 100 0, 5 000 мешков, 250 000 кг.**
Тип ставки — не установлена (0 %): сахар позиции 1701 не включён в постановления
Правительства РФ о вывозных пошлинах. **Пошлина к уплате: 0 ₽**, таможенный сбор **8 262 ₽**,
курс валюты не требуется. Сертификаты: регистрация производителя в GACC (CIFER) —
**срок 2–6 месяцев**, сертификат происхождения общей формы ТПП РФ, экспортная декларация ЭК 10.
Предупреждения: без регистрации GACC партию не пропустят; сертификаты ЕАЭС в КНР
не признаются; 250 т не помещаются в один 20-футовый контейнер — нужно 11 контейнеров.
Отчёт приходит тремя сообщениями (1/3 … 3/3) плюс файл `.txt`.

**Сценарий 2 ТЗ. Армения, мёд натуральный 0409 00 000 0, 200 единиц, 4 000 кг.**
Пошлина **не применяется (ЕАЭС)**, итого **0 ₽**; таможенные сборы не взимаются, курс валюты
не требуется, НДС 0 %. Декларация: статистическая форма учёта перемещения товаров
(ПП РФ № 891) до 10-го рабочего дня следующего месяца; декларация на товары не подаётся.
Сертификаты: **ветеринарный сертификат формы № 2 ЕАЭС** (мёд — продукция животного
происхождения) и регистрация предприятия в реестре ЕАЭС (ФГИС «Цербер»).

**Сценарий 3 ТЗ. Казахстан, мука пшеничная 1101 00 00 00, 1 000 мешков, вес «5».**
(В ТЗ код записан как `1101 00 00 00`; бот показывает его в принятой группировке — `1101 00 000 0`.)
Предупреждение: «⚠️ Указанный вес одной единицы (0,005 кг) выходит за типичный диапазон
для «Мука пшеничная» (обычно 1–51 кг). Проверьте данные». Бот предлагает уточнить —
«в тоннах», «в килограммах» или «всё верно», а кнопка «✏️ Изменить данные» возвращает
к вводу веса без потери страны и кода. После исправления на 50 000 кг: пошлина не применяется
(ЕАЭС), **фитосанитарный сертификат** (продукция растительного происхождения), маркировка
на русском и казахском языках.

**Комбинированная ставка. Китай, рапс 1205 10 900 0, 100 единиц, 100 000 кг.**
Ставка — 30 % от таможенной стоимости, но не менее 165 € за 1 000 кг.
Расчёт по стоимости: 4 300 000 × 30 % = 1 290 000 ₽. Расчёт по весу:
100 000 ÷ 1 000 × 165 € × 100 ₽ = **1 650 000 ₽**. **Итого к уплате: 1 650 000 ₽**
(расчёт по весу даёт большую сумму), таможенный сбор **21 344 ₽**,
всего платежей **1 671 344 ₽**.

## 14. Известные ограничения

- **Данные учебные**, собраны на 20.09.2026. Ставки, требования и курс могли измениться;
  каждый отчёт сопровождается дисклеймером MVP.
- **Базы данных нет** (ТЗ §19): расчёты и сессии живут в памяти 24 часа и теряются при
  перезапуске программы.
- **Один токен — одна копия бота.** Со второй копией на том же `BOT_TOKEN` бот перестаёт
  отвечать: перед запуском на сервере остановите локальный `docker compose down`.
- **Только личные диалоги** — работа в группах и каналах не поддерживается.
- **Три страны и фрагмент справочника ТН ВЭД — 58 кодов** (56 пищевых): товара вне
  справочника бот не найдёт.
- **Коды из ТЗ отсутствуют в действующей ТН ВЭД ЕАЭС.** `1701 12 100 0` (сахар-песок)
  и `1101 00 00 00` (мука) в номенклатуре не значатся. Оставлены, чтобы тестовые данные ТЗ
  работали, и помечены в отчёте с действующими аналогами (`1701 99 100 1` / `1701 99 100 9`
  и `1101 00 150 9` / `1101 00 110 9`).
- **Курс учебный:** 1 € = 100 ₽, 1 $ = 90 ₽, 1 ¥ = 12,5 ₽; официальный курс ЦБ РФ включается
  переменной `RATE_SOURCE=cbr`. **Таможенная стоимость — учебная оценка** по цене за тонну
  из справочника, а не из контракта: цены контрактов запрещены к использованию (ТЗ §17).
- **Вне MVP (ТЗ §19):** проверка контрагентов, инкотермс, генерация документов, логистика
  и страхование, отслеживание груза, валютный контроль, уведомления об изменении ставок;
  нет авторизации, ролей, мониторинга, резервного копирования и SLA.
- **Мини-приложение MAX отменено 24.09.2026.** В MVP реализован только чат-бот; HTTP API
  остался служебным — по нему можно проверить расчёты без мессенджера.

## 15. Остановка и повторный запуск

Локально, из папки проекта:

| Задача | Команда |
|---|---|
| Остановить | `docker compose down` |
| Запустить в фоне | `docker compose up -d` |
| Запустить с пересборкой | `docker compose up -d --build` |
| Перезапустить | `docker compose restart` |
| Журнал | `docker compose logs -f` |
| Состояние | `docker compose ps` |

На сервере — те же команды из папки `/opt/maxexport`; разворачивание и обновление одной
командой: `./scripts/deploy.sh root@адрес-сервера`, подробности в [`docs/deploy.md`](docs/deploy.md).

**После перезагрузки сервера** бот поднимается сам: у контейнера задано `restart: unless-stopped`.
Расчёты и сессии при этом не сохраняются — диалог начинается заново.

### Сделано сверх ТЗ

| Что | Зачем |

### Расхождения с ТЗ

| Расхождение | Почему |
|---|---|
| **Коды ТН ВЭД из ТЗ §9 и §22** — `1701 12 100 0` и `1101 00 00 00` — в действующей ТН ВЭД ЕАЭС отсутствуют | Оставлены, чтобы тестовые данные ТЗ работали. В отчёте помечены ℹ️ с указанием действующих аналогов |
| **Сертификат происхождения — общая форма ТПП РФ, а не «форма EAEU–China»** (ТЗ §12) | Соглашение ЕАЭС–КНР 2018 года непреференциальное: преференциальной формы сертификата по нему нет, применяется ставка MFN |

| **Приветствие начинается с «MAXimum Export —», а не с «МАКС —»** (ТЗ §15, экран 1) | «МАКС» путается с названием мессенджера. Решение команды от 22.09.2026 |

| **Мини-приложение не реализовано** | Отменено решением от 24.09.2026: в MVP только чат-бот |

## 18. Фиксация версии

Версия, отправленная на конкурс, — это коммит в локальном git-репозитории проекта.
Его хеш и архив с контрольной суммой готовятся одной командой:

```bash
./scripts/release.sh
```

Скрипт проверяет, что нет незакоммиченных изменений, прогоняет `go vet` и `go test ./...`,
собирает архив коммита `dist/maximum-export-<хеш>.tar.gz` и файл с контрольной суммой
`dist/maximum-export-<хеш>.tar.gz.sha256`.

Проверить архив у себя:

```bash
shasum -a 256 -c dist/maximum-export-<хеш>.tar.gz.sha256
```

Папка `dist/` не входит в репозиторий: архив собирается из коммита, а не хранится в нём.
